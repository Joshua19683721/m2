# 場景式英文輸入練習 · A2 Key

依照**生活場景**分類，用「逐字打字」的方式練習**單字、片語、句子**的英文輸入。
架構沿用 [wordmomo](https://joshua19683721.github.io/wordmomo/) 的循序漸進拼寫練習，
詞彙範圍完整涵蓋 **Cambridge English《A2 Key / A2 Key for Schools Vocabulary List》
（© UCLES，2025 年 8 月版）**。

純前端、離線可用，沒有任何外部相依套件。

## 四種練習模式

| 模式 | 做法 | 適合 |
|---|---|---|
| **單字** | 一個單字一個輸入框，只比對字母 | 抓 `-ed` / `-s` / `-le` 的拼字問題 |
| **片語** | 一個詞一個輸入框 | 熟記固定搭配（`a piece of cake`、`at the weekend`） |
| **句子** | 逐詞輸入，標點自動跳過 | 練大小寫、標點、單複數 |
| **盲打整句** | 不給提示，整句一次打完，逐詞標紅 | 最接近考試的輸入方式 |

輸入框只接受「正確答案的前綴」，打錯會震動退回上一個字；
同一個字錯 3 次自動浮出提示並朗讀（次數可調）。
不會自動跳到下一張，要自己按 Space 或 Alt+N。
輸入框另設 `maxlength` 與長度鉗制，任何情況下都不會比目標字長。

### 「💡 提示」開關（預設關閉）

| | 中文 | 英文原句 | 音標 | 輸入框上方浮水印 |
|---|---|---|---|---|
| **勾選** | 顯示 | 顯示 | 顯示 | 顯示 |
| **不勾選**（預設） | 顯示 | 隱藏 | 顯示 | 隱藏 |

同一個字錯 3 次的自動提示也受這個開關控制：不勾選就全程不顯示那個單字。

**打不出撇號的問題已經處理。** `Who's`、`It's`、`o'clock` 裡的 `'`，
在下列情況下打出來的不是半形 ASCII `'`（U+0027），但螢幕上完全看不出來：

| 情況 | 實際打出來的字元 |
|---|---|
| 中文輸入法在**中文模式**按單引號鍵 | 全形撇號 `＇`（U+FF07） |
| 文字處理軟體自動替換 | 智慧引號 `’`（U+2019） |
| macOS 預設鍵盤的 `'` 鍵 | 死鍵（Dead key），要等下一個鍵才出字元 |
| 全形模式 | 全形英文字母 `Ｗｈｏ` |

App 現在統一處理：

1. **正規化**：全形 `！`～`～`（U+FF01–U+FF5E）一律減 0xFEE0 變半形；
   智慧引號、反引號、acute 一律變成 `'`；全形空白變半形。
2. **去雜訊**：剩下的中文、標點、空白等「不是答案字元」的部分**靜默丟掉**，
   不記錯誤、不震動——那是輸入法的產物，不是學生打錯。
3. 只有「是答案字元但內容不符」才判定為真的打錯。

`node tools/test_apostrophe.js` 有 27 項測試涵蓋上述各種情況，
另包含「接線檢查」，確保 `onInput` 真的有呼叫這兩個處理函式、`onKey`
沒有又把字元擋掉（防止日後改版把修正弄掉）。

### 另一個容易誤會的地方：字型不是字元

詞庫裡的撇號**本來就全部是半形 U+0027**（`python tools/check_quotes.py` 可驗證，
41 筆全數乾淨，沒有一個 `’` 或 `＇`）。但 **Consolas 會把 U+0027 畫成彎的、像逗號**，
學生看到浮水印上的 `’` 會以為答案是彎引號，打直撇號反而被判成打錯。

所以打字區的字型改成 **Courier New**：

```css
--font-type: 'Courier New', Courier, Consolas, 'DejaVu Sans Mono', monospace;
```

它的 `'` 是一條直的豎線，才是真正的打字機單引號外觀，而且整體更像一份
「要照著打的稿子」。音標維持 Consolas，因為 Courier New 對 `ˈ ˌ ː ɪ ʊ ə`
這些 IPA 字符的覆蓋不完整。

想在自己的電腦上比較各種字型的撇號外觀，瀏覽器打開 `tools/quote-font.html` 即可。

### IME 組字中不要碰輸入框

中文輸入法在中文模式組字時，瀏覽器會**持續送出 `input` 事件**，
中間的值是還沒確定的暫態。早期版本會照樣跑驗證、還會改寫 `input.value`，
結果就是把 IME 的組合狀態弄壞——**這正是「撇號怎麼打都打不出來」的真正原因之一**。

現在的處理：

* `onInput` 一進來先看 `e.isComposing`，**組字中直接 return，完全不碰輸入框**。
* 每個輸入框都掛 `compositionstart` / `compositionend`：
  確定之後瀏覽器不一定會再送一次 `input`，所以 `compositionend` 會主動補跑一次驗證。
* 偵測到組字中，或單元裡含撇號時，畫面會跳出黃色提示：
  **「請按 Shift 或 Ctrl+Space 切到英文（半形）模式」**，
  並明講這一題的撇號必須是直的 `'`（U+0027），全形 `＇` 雖然看起來像，
  鍵盤上打不出來也會被判錯。

`node tools/test_apostrophe.js` 現有 32 項測試，其中 9 項是「接線檢查」，
確保上面這些保護日後改版不會被悄悄移除。

盲打比對用 **LCS（最長公共子序列）對齊**，漏一個字不會讓後面整句都錯位。
結果分成四種顏色：綠色正確、紅色打錯、紅色漏打、黃色多打，
正確率＝正確字數 ÷ 目標字數。盲打只比對文字本身，標點不列入計分。

## 解析面板的詞性是怎麼來的

「句子結構與詞性對照表」不是用關鍵字猜的。`tools/build_scenes.py` 會從
Cambridge 官方詞表的詞性標註產生一份 **1,603 筆單詞 + 135 筆片語**的對照表
（`window.SCENE_POS`），App 直接查這份表。

查不到時才依序退回：不規則形表（`children`、`bought`…）→ 詞形規則
（複數 `-s/-es/-ies`、過去式 `-ed/-ied`、進行式 `-ing`、比較級 `-er/-est`）
→ 啟發式。**例句用詞的詞性命中率 97%**，剩下的多為官方表未收錄的專有名詞。

官方表把多義詞都列出來（`glass` 是 `n & adj`、`film` 是 `n & v`、
`that` 是 `conj & pron`），所以還需要**上下文**才能決定這一句裡是哪一個：

| 判斷依據 | 效果 |
|---|---|
| 在主詞位置 | `The film` → film 當**名詞** |
| 緊跟在限定詞後面 | `a glass` → glass 當**名詞** |
| 後面接標點或句尾 | `please,` → **感嘆詞** |
| 後面是「名詞 + 動詞」 | `that I fell` → **連接詞**（that 子句） |
| 前面是 be 動詞 | `There is` → **虛擬主詞** |

情態動詞開頭的句子（`Can I …`）會往前找回真正的主詞。

## 進度與資料

* 練習進度（練到第幾張、哪些字已打好、最佳秒數）存在瀏覽器 `localStorage`，
  設定面板可**匯出／匯入**進度，或直接匯出 `scenes.js` 搬移到別的裝置。
* 統計頁會顯示完成單元數、總字元數、平均正確率、累積錯誤、練習天數與分鐘數。
* 首頁有**今日挑戰**（每天 20 張）與 **🎲 隨機挑戰**：跨場景、跨模式抽一張，
  沒練過的單元權重是已練過的 3 倍，所以會自然往還沒練的地方跑。
* 儲存層採**記憶體快取 + 延遲寫回**：連續打字時不會每敲一個字就把整份進度
  重新序列化寫進 localStorage（那會在打字時卡頓）；離開頁面或分頁隱藏時一定寫回。
* 盲打模式的單元清單在「還沒動過之前」不會顯示英文答案，只給中文提示。
* 統計頁附**錯題本**：跨全部場景與模式，按「累計錯誤次數」排序。
  這個次數是累積的——就算後來練對了也不會消失，正是需要多複習幾次的地方。
  點一列直接跳回該場景該模式的那一張。
* **按鍵正確率 =（打對的字元 ÷ 全部按鍵）× 100%**，是真實測量。
  （早期版本這裡寫的是 `100 − 錯誤率 × 3`，那個 3 是憑空乘上去的，
  數字會很好看但不是事實，已經拿掉。）

## 音標是怎麼來的

單字與片語的音標由內容編輯人工撰寫（英式 IPA，音節以小圓點分隔，
主要重音 `ˈ`、次要重音 `ˌ`，不含前後斜線）。

**例句的音標是 App 執行時即時組合的**，避免人工標 840 個句子時出錯：

1. 開場時把全部場景的單字／片語音標登錄進全域字典（約 3,450 筆）。
2. 內建一份 A2 高頻**功能詞**音標表（代詞、冠詞、情態動詞、介系詞、連接詞…）。
3. 逐詞用**最長片語匹配**查字典，查不到就套用詞形規則
   （複數 `-s/-es/-ies`、過去式 `-ed/-ied`、進行式 `-ing`、比較級 `-er/-est`、所有格 `'s`），
   不規則變化（`bought`、`teeth`、`children`…）另有一張補丁表。
4. 連續發音修正：`a` 在母音前唸 `eɪ`、`the` 在母音前唸 `ði`、相鄰重音降為次重音。
   片語開頭是 `a` / `the` 時（例如 `a glass of water`）不會被冠詞規則改寫。
5. **任何一個字查不到，整句就不顯示音標**（寧可不出，也不出錯的音標）。

目前 **840 / 840 個例句（100%）** 都能完整組合出音標。
執行 `node tools/selftest.js` 可看到統計，`node tools/diagnose_ipa.js` 可列出還查不到的字。

### 中文用字：臺灣正體

詞庫的中文一律是**臺灣正體**，並且不接受簡體字。

這件事不能用「轉換器全掃」解決。實測 `python tools/scan_simplified.py`：
專案 1,865 個漢字裡只有 15 個字會被 OpenCC `s2t` 改動，其中 14 個在臺灣本來就該維持原樣——
用轉換器反而會改錯：

| 字 | 轉換器會改成 | 為什麼不能改 |
|---|---|---|
| 吃 ×41 | 喫 | 臺灣用「吃東西」 |
| 游 ×24 | 遊 | 「游泳」「游泳池」用游，只有「旅遊」用遊 |
| 台 ×20 | 臺 | 「月台」「服務台」「台灣」用台 |
| 床 ×13 | 牀 | 臺灣用「床」 |
| 群 ×11 | 羣 | 標準寫法是「群」 |
| 里 ×7 | 裏 | 「公里」「英里」用里 |
| 划 ×4 | 劃 | 「划算」「划船」本來就對 |
| 丑 ×2 | 醜 | 「小丑」用丑 |
| 后 ×1 | 後 | 「皇后」用后 |
| 斗 ×1 | 鬥 | 「熨斗」用斗 |
| 伙 ×1 | 夥 | 「傢伙」用伙 |

**真正需要改的只有 4 個詞、6 處**，已修：
`喝采→喝彩`、`精采→精彩`、`占→佔`、`形容词→形容詞`
（`python tools/fix_traditional_words.py`）。

建置腳本裡有一道**常駐關卡**：每一筆 `zh`、`summary`、`note`、`tips` 都會檢查是否含簡體字，
有就直接擋下建置。白名單（上面那些字）連同原因寫在 `build_scenes.py` 的 `TRAD_OK`，
避免日後有人「好心」把它刪掉。關卡本身有用 `tools/test_simplified_gate.py` 驗證過——
它會故意塞簡體字進去，確認建置腳本真的會擋。

### 品質驗證

`tools/build_scenes.py` 會擋下這些問題：單字／片語缺 `ipa`、句子誤帶 `ipa`、
`en` 為空、`en` 含彎引號、`zh` 含拉丁字母（括號內的英文例詞除外）、`zh` 為空、
場景 id 重複、規格指定但漏掉的詞（含 `all right/alright` 這類複合拼法的變體判定）。

`node tools/test.js` 另外驗證 115 項行為：音標組合規則、盲打 LCS 對齊的正確性、
資料不變量、100% 覆蓋率、詞性判斷（含多義詞的上下文選擇）、儲存層的讀寫次數、隨機挑戰的取樣範圍與權重、錯題本的累計錯誤與排序；
有任何回歸就會 exit 1。

建置腳本另有一道**音標字元集關卡**：只接受英式 IPA 字母、重音符號、長音符號與
音節分隔點，出現漢字、全形空白或其他雜訊會直接擋下（先前就靠它抓到過
一條被誤植全形空白的音標，和一條漏收合法 IPA 母音的規則）。

內容正確性做過兩輪獨立稽核（共 20 個批次）：英文文法、自然度、詞義、
繁體中文台灣用語、音標、難度、重複、場景內一致性。
第一輪 92 則問題、第二輪再抓到其餘遺漏，修正紀錄保留在
`data/qa/manual_fixes.json`（支援 `zh` / `ipa` / `en` / `delete` 四種欄位）。
